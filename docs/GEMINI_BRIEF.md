# アプリ仕様 申し送り（Claude Code / Codex → Gemini Spark）

このファイルが唯一の正本です。`npm run sync-gemini` でスプレッドシートの
『アプリ仕様_Claude→Gemini』タブへ全文が転写されます。

---

## 1. このアプリの役割

薫之介さん専用のモバイルダッシュボード（Next.js / Vercel）。
スプレッドシートを共通データベースとして、Gemini Spark と役割分担しています。

- **Gemini Spark**: 食事写真の解析、カロリー/PFCの算出、朝食後の当日メニュー立案、歩数・睡眠・筋肉痛・今日の予定・朝食の反映 → **スプレッドシートに書く**
- **アプリ**: 体重・筋トレ実績の記録 → **スプレッドシートに書く**
- **アプリ**: Gemini が書いた数値と計画を **読んで表示する**

### 2-b. 3AI共通の必読・記録ルール

Claude Code / Codex / Gemini Spark は、スプレッドシート、アプリ仕様、データ書式、AI役割に関わる作業をする前に、
必ず次の順番で確認してください。

1. `AI運用ルール_必読`
2. `AI変更履歴` の最新20件
3. `AI会話議事録` の最新20件
4. `アプリ仕様_Claude→Gemini`
5. Google Docs `15kg減量＆ボディメイクプロジェクト_指示書`
6. `CLAUDE_MD_MASTER` / 各ツールのローカル指示ファイル

変更後は必ず記録します。

- シート、GAS、アプリ、仕様文書、データ書式、AI役割を変更したら `AI変更履歴` に追記。
- ユーザーとの会話で要件・運用・役割・食事/運動方針が決まったら `AI会話議事録` に追記。
- Geminiの日常コーチングや毎回参照する前提が変わる場合は、Google Docs 指示書にも反映してください。
- 所有者が曖昧なセル、既存データを消す編集、他AIの担当領域に触れる編集は、ユーザー確認なしに進めない。

## 3. 日次ログ（A〜K列）の書式

| 列 | 項目 | 主に書く人 |
|---|---|---|
| A | 日付 `YYYY-MM-DD` | 両方 |
| B | 体重(kg) | アプリ |
| C | 摂取カロリー(kcal) | Gemini |
| D | タンパク質P(g) | Gemini |
| E | 脂質F(g) | Gemini |
| F | 炭水化物C(g) | Gemini |
| G | 消費カロリー(kcal) | Gemini |
| H | 歩数 | Gemini |
| I | 筋トレ部位・メニュー | **アプリ専用** |
| J | その他運動 | Gemini |
| K | メモ・コンディション | Gemini |

### I列（筋トレ実績）の取り扱い — 重要

**筋トレの実績入力はアプリの担当です。Gemini は I列に書かないでください。**
薫之介さんがジムでアプリに1セットずつ入力し、アプリが I列へ次の書式で書き込みます。

```
[胸]ベンチプレス: 60kg×10回, 65kg×8回 / [腕]アームカール: 12kg×12回 ｜ 計3セット/負荷量1996kg
```

- 種目の区切りは ` / `、セットの区切りは `, `
- 各セットは `重量kg×回数回` （**末尾の「回」は必須**）
- ` ｜ ` 以降は自動集計。アプリが再計算するので手で直す必要はありません

アプリはこの I列を読み戻して「筋トレ」タブの履歴・合計負荷量・記録日数に反映します。
`回` の無い旧書式（`ダンベルプレス［8kgx10, 13.5kgx5］`）も読めますが、
Gemini が実績を書く必要はありません。**計画は §4（進捗＆予測ダッシュボード）に書いてください。**

### H/K列（朝報告データ）の取り扱い — 重要

朝食後、薫之介さんは Gemini Spark に `昨日の歩数 / 睡眠時間 / 今朝の筋肉痛 / 今日の予定 / 朝食` をチャット報告します。
Gemini は次のようにシートへ反映してください。

```
昨日の歩数 → 昨日の日付の H列
睡眠・筋肉痛・今日の予定・朝食 → 今日の日付の K列
睡眠: 7.5時間 / 筋肉痛: 胸, 腕 / 今日: 大学, バイト / 朝食: ご飯, 卵, 味噌汁
```

- アプリは H列/K列を上書きしません。
- アプリは K列を正規表現で解析します。`睡眠: X / 筋肉痛: X / 今日: X / 朝食: X` の各キーは順不同でも読めますが、
  Gemini はこのキー名と `:` または `：` を維持してください。
- 「今日」タブはこの反映状況と今日のAI計画を見る画面です。

### J列（その他運動・有酸素）の取り扱い

ホームの有酸素FatMaxメーターは、今週の J列テキストから `30分` / `1時間` などの時間表記を読み取り、
週間累計分数を算出します。Gemini は有酸素や水中歩行を記録するとき、次のように時間を必ず入れてください。

```
ウォーキング 35分
水中歩行 45分
LISSバイク 30分
```

## 4. AI次回計画メニューの書式 — 重要

`進捗＆予測ダッシュボード` タブの**任意のセル**に、次の形式で書いてください。
アプリは全シート・全セルを走査して見出しを探します。

```
AI次回計画メニュー (2026/08/10 Push 自宅)
ダンベルベンチプレス: 8kg*2*10(アップ), 24kg*2*8(メイン1), 18.5kg*2*10(バックオフ) | レスト150秒
フレンチプレス(両手): 12kg*1*12 | レスト60秒
```

- 見出し: `AI次回計画メニュー (YYYY/MM/DD 部位 場所)`
- 見出しの**直下の行から空行まで**を1つの計画として読みます。
- 各行: `種目名: 重量kg*本数*回数(ラベル), ... | レストN秒`
  - `本数` はダンベルの個数（2 = 両手）
  - ラベルに「アップ」を含むセットはウォームアップ扱いで、目標回数の算出から除外します
  - レストは `分` でも可（`レスト2.5分`）
- アプリはこれを筋トレ画面にワンタップで取り込み、重量・回数・レスト秒をプリセットします。

## 5. 絶対禁止（NG）種目

- **ダンベルフライ**: 提案しないでください。アプリ側でもプリセットから完全除外しています。

## 6. 店舗別の機材ルール

- **赤坂店 (LifeFit)**: レッグカール**なし** / アシストチンニング**あり**
- **牛久・自宅近く店 (LifeFit)**: レッグカール**あり** / アシストチンニング**なし**

## 7. 現在の機能一覧

**ホーム**
- 体重推移グラフ（実測値の点 + 14日EMA実質体重線 + 未来のPhase目標ガイドライン点線。機械的な直線予測は表示しない）
- スタート体重は正本の 90.0kg 固定。記録内の最大体重を開始基準にしない
- 科学KPIカード:
  - ノイズ除去した実質体重: `Y_t = 0.133 * X_t + 0.867 * Y_{t-1}`。補足は「水分ブレを除いた体重」
  - 今週の減量スピード: `(Y_t - Y_{t-7}) / Y_{t-7} * 100`。安全圏は 0.5〜1.0% BW/week
  - 実測消費代謝量 (TDEE): 直近14日平均摂取カロリーと14日前からの実質体重変化から逆算
    `TDEE = avgIntake14 - (8300 * deltaTrendWeight14 / 14)`
  - 計算上の純脂肪カット量: アンダーカロリー累計 ÷ 8,300 kcal。補足は「水分を除く純脂肪の減量分」
- 未来の目標ガイドラインは、最後の実質体重からPhase 1→2→3の目標週減量kgで右側の未来日付へ伸ばす点線です。
  「計画より何日遅れ」の判定ではなく、今後の減量イメージ用のガイドです。
- 3 Phase減量ロードマップ:
  - Phase 1 初期高効率: 90kg→84kg / 0.8% BW/week / 2,000 kcal (P155 F44 C245)
  - Phase 2 Vシェイプ加速: 84kg→79kg / 0.6% BW/week / 1,950 kcal (P165 F43 C225) / リフィード表示
  - Phase 3 極限絞り込み: 79kg→75kg / 0.5% BW/week / 1,900 kcal (P175 F46 C195) / ダイエットブレイク表示
- 本日のカロリー・PFC・歩数（Gemini がシートに書いた値を表示）
- 筋肉保護インジケーター:
  - 睡眠アナボリック: K列の睡眠から 7.0時間以上=正常、6.0〜6.9時間=注意、5.5時間未満=筋分解リスク高
  - ディロード: I列筋トレ実績の連続トレーニング週が4週以上で推奨表示
  - 有酸素FatMax: J列の今週有酸素累計を180分上限でゲージ化。超過時は筋分解干渉注意
  - LBMタンパク質: LBM 70.2kg 基準で 155〜175g/日の達成ゲージを表示
- 本日のAI計画カード

**今日**
- 朝食後のGemini報告の反映状況（昨日歩数・睡眠・筋肉痛・今日の予定・朝食）を表示
- K列睡眠から「睡眠アナボリック＆筋肉保護」ステータスを表示
- 朝に確定した今日のAI計画を表示
- アプリから記録するのは体重のみ。スプレッドシート連携時は B列へ反映

**筋トレ**（実績入力はすべてここ）
- 「筋トレMEMO」風の赤基調UI、カレンダー、今月/累計の合計負荷量・記録日数
- **過去のトレーニング履歴**: アプリの記録と I列 の内容をマージして日付順に表示。
  タップで種目・全セット・負荷量を展開でき、そのまま入力欄に読み込んで編集できる
- AI計画のワンタップ取り込み
- レストタイマー（60/90/120秒）、1RM自動計算
- **種目の自作追加・削除**（プリセットに無い種目に対応）

※「履歴」タブは廃止し、筋トレ履歴は上記に、体重・カロリー推移はホームに統合しました。

**設定**
- 各ユーザーが自分のスプレッドシート（GASウェブアプリURL）を登録
- 未連携でも記録は端末に保存される。連携するとカロリー分析とAI計画が有効になる

## 8. マルチユーザー構成

サーバー側に共有の接続先は持ちません。各ユーザーが自分のシートを登録する方式なので、
**他人が薫之介さんのシートを見ることはできません。**
新規ユーザー向けに、数値の入っていないテンプレートを配布しています。

## 9. Gemini Spark へのお願い

1. カロリー・PFC・消費カロリー・その他運動は**シートに直接**書いてください（アプリは読むだけです）。
2. 朝食後に当日メニューを §4 の書式で書いてください。書式が崩れるとアプリが読み取れません。
3. H列（歩数）とK列（`睡眠: / 筋肉痛: / 今日: / 朝食:`）は Gemini の領域です。アプリは上書きしません。
4. **I列（筋トレ実績）はアプリの領域です。**Gemini は書かないでください。
   Gemini の担当は「朝の当日**計画**」（§4）で、「当日の**実績**」はアプリが書きます。
   実績を上書きすると、筋トレタブの合計負荷量と記録日数がずれます。
5. CLAUDE.md を更新するときは `CLAUDE_MD_MASTER` の A1 に**全文**を入れてください。
   セクションを削ると、その仕様がローカルから失われます。
6. Claude Code と Codex は、このリポジトリでは同じ「開発・データ解析・仕様連携」担当として扱ってください。
   Codex が更新したアプリ仕様やデータ書式の申し送りも、Claude Code からの申し送りと同じ重みで参照してください。
7. 作業前に `AI運用ルール_必読`、`AI変更履歴` 最新20件、`AI会話議事録` 最新20件を確認してください。
   何かを書き換えた場合は、必ず `AI変更履歴` または `AI会話議事録` に記録してください。
8. Gemini Spark は Google Docs `15kg減量＆ボディメイクプロジェクト_指示書`
   (`1K_0vo2KIpjdZDmvC3bhLQREIQekqTSSR-gOBOd17jnY`) を毎回参照するため、
   日常コーチングや運用前提に関わる変更はこのDocsにも反映してください。
